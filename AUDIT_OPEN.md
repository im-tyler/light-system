## Upstream ontos mirrors (OTO-016/OTO-017, 2026-09-12) - closed

- **OTO-016 mirror (contact sweep reaches coarse-low static pairs): fixed.** ontos 89afa2e made section 24 static contact positional rather than id-constrained; the dump's pair sweep still required the outer index to be fine, so a stream with a coarse contactant below the fine body would have been blessed wrong (the pre-fix dump silently computes zero contacts for a pair ontos records). The sweep now visits every unordered real-body pair in pinned (i, j) order and dispatches on membership; keys/record ids stay (min, max). Verified: all 13 committed corpora byte-identical (stdout + WAV), plus a generated negative stream exercising the orientation (seed 117, count 8, region 2 demoted at tick 1; produced by ontos at aa305ee through an out-of-tree path-dep generator, so no corpus or ontos change was needed) - the fixed dump verifies it bit-exactly incl. the audio hash, the pre-fix dump fails with a contact count mismatch. Stream kept out of the repo (regenerate via the setup above).
- **OTO-017 mirror (shell classification precedes the global scale): fixed.** ontos edff03b pins section 25 step 2 (classify the unscaled base) before step 3 (solve/apply lambda); the dump classified the scaled radii about the scaled mean, which can flip near-tie shell membership under binary64 rounding and bless a wrong expansion. Verified: all corpora byte-identical (no committed corpus carries near-tied radii - same as ontos goldens); the ordering is pinned by a temp include-harness unit check reproducing the ontos frozen sqrt(185) near-tie constants (pre-scale classification closes every shell on its record binding; the old order flips the tie and misses two; harness fails on the pre-fix source). No stream-level corpus is possible without an ontos corpus hook (exact-tie layouts are not reachable from seeded ICs - probability ~1e-14), matching ontos, which pins this by unit regression rather than corpus.

## Open decisions for the owner

- **LS-24 (contract decision, no behavior change): cross-toolchain byte identity of generated normals is unpinned.** The builder computes normals with host `sqrt`/`acos` and the prototype CMake does not pin FP contraction (`-ffp-contract`), so the same source asset can produce different normal bytes under different compilers/FP environments, and a content-addressed cache keyed on those bytes is not portable across toolchains. Options: (a) pin FP semantics for the builder (contraction off, explicit math where practical) and quantize normals at serialization so byte identity is a contract; or (b) keep generation unpinned and make cross-platform cache tests semantic (compare decoded values with tolerance) instead of byte-exact. Owner to rule; nothing committed either way. The schema-version pin check from LS-25 (`tools/check_schema_version.sh`, CI) is in.
- **LS-54 future work (rejected-not-implemented, by ruling of this pass): payloads over `maxStorageBufferRange`.** The clean rejection now in place (see pass 6 notes) is the fix; splitting payloads across multiple descriptor bindings or moving the shaders to 64-bit addressing are the upgrade paths if assets ever outgrow the ~128 MiB core-minimum range. Not scheduled.

## Fixed in scout pass 4 (LS-35..LS-42, LS-24 excepted)

- **LS-35 (glTF mirrored-instance winding): fixed.** The importer computes the world-transform determinant per node and reverses triangle winding (swap b/c) for indexed and non-indexed primitives when it is negative, before clustering; shader untouched. Verified with identity vs. `-1`-scale node fixtures (indexed and non-indexed): `0,1,2` vs `0,2,1`. Positive-determinant assets produce byte-identical winding to before.
- **LS-36 (residency bootstrap modes): fixed.** `create_residency_model` takes a `ResidencyBootstrapMode` (default `all` preserves the viewer runtime) and establishes exactly the advertised set with the complement unloaded; `none` asserts zero resident pages; the mode-string parsing is centralized in `runtime_model` and `replay_script` delegates to it. Behavior change: `meridian_replay`/`meridian_residency` frame-0 output for `none`/`base-only`/`lod-only` now reflects those sets (previously all three behaved like `all`). CI checks exit codes only; committed replays still pass. `benchmarks/scripts/run_import_validation.py` re-runs replays but compares no frame-0 counts.
- **LS-37 (swapchain caps intersection): fixed.** Usage intersects `supportedUsageFlags` (TRANSFER_SRC requested only when supported; recorded in `SwapchainContext.images_support_transfer_src`), composite alpha prefers OPAQUE then falls back through supported modes. The screenshot path fails explicitly at request time (stderr + no capture) when TRANSFER_SRC is unavailable, not at startup.
- **LS-38 (screenshot byte order): fixed.** Readback swizzle is driven by `surface_format.format` (BGRA8/RGBA8, UNORM or SRGB); other formats are rejected at capture time with an explicit error instead of writing corrupted output.
- **LS-39 (instance extension availability): fixed.** `VK_KHR_get_physical_device_properties2` is no longer requested (core since 1.1, requested apiVersion 1.2); `VK_KHR_portability_enumeration` and its instance-create flag are enabled only when the loader advertises the extension.
- **LS-40 (texture upload one-shot checks): fixed.** `vkAllocateCommandBuffers`/`vkBeginCommandBuffer`/`vkEndCommandBuffer` are checked with the LS-21 unwind pattern (pool + staging destroyed, error propagated).
- **LS-41 (timestamp wrap): fixed.** The profiler records the graphics queue family's `timestampValidBits` at creation and computes deltas modulo 2^bits (identity at 64); wrap math pinned by static_asserts (no runtime profiler test surface exists; compile-time checks follow the gpu_abi.h convention).
- **LS-42 (bootstrap exit code): fixed.** `meridian_vk_bootstrap` returns 4 with a stderr diagnostic on initialization/submission/fixed-count present-loop failure; completed fixed-frame runs and clean interactive closes return 0. `benchmarks/godot/run_bench.sh` (exit-code-sensitive via `set -e`) expects success on healthy runs and is unaffected.

- **LS-47 (cluster triangle limit vs visibility ABI): fixed.** Manifest validation rejects `cluster_triangle_limit > 256` (visibility stores `local_triangle` in 8 bits; larger limits alias ids). Boundary 256 and all committed manifests (max 124) unaffected; widening the format stays out of scope.

- **LS-23 reopened (fingerprint metadata coverage): fixed.** `compute_content_fingerprint` now folds in the full header/summary metadata the sidecar mirrors (asset_id, source_asset, has_fallback, source counts, textured flag, texture dims, bounds, all totals) on top of payload + page layout. **Fail-closed consequence: fingerprints changed; .vgeo + .summary.txt pairs persisted before 2026-09-12 fail the pairing check on import and must be regenerated (rebuild the asset).** Schema version stays 6; the documented fingerprint definition in `schemas/VGEO_RESOURCE_SCHEMA.md` is updated. ## Fixed in scout pass 6 (LS-52..LS-62, LS-23 3rd reopen; 2026-09-12)

- **LS-52 (--threads parse + executor startup): fixed.** `--threads` parses via `from_chars` full-string with a 1024 cap (`-1`, `4x`, `99999999` all rejected with a named usage error; `atoi` used to wrap -1 to 4294967295 threads). The `ParallelExecutor` constructor is exception-safe: if worker N fails to start, the already-started workers are stopped (stop flag + notify) and joined before the rethrow -- previously the member vector's destruction hit `std::thread::~thread` on joinable threads (std::terminate), because destructors do not run for a partially constructed object.
- **LS-53 (cluster_vertex_limit range): fixed.** Manifest validation enforces 3 <= cluster_vertex_limit <= 256, citing the pinned meshoptimizer clusterizer's `assert(max_vertices >= 3 && max_vertices <= 256)` (meshopt_Meshlet local vertex indices are one byte). Boundary-verified: 2 and 257 fail with the named BuilderError; 3 and 256 build.
- **LS-54 (payloads vs maxStorageBufferRange): fixed by clean rejection.** After device creation (before any descriptor write or upload), `vkGetPhysicalDeviceProperties().limits.maxStorageBufferRange` is compared against the base and LOD payload sizes; an oversized resource fails with a status naming the payload, the sizes, and the limit (bootstrap exits 4 via the existing verdict path). Both upload modes covered: demand-streaming allocates the payload buffers at full size too. Splitting/64-bit indexing deferred - see the owner-decision note above.
- **LS-55 (visibility 22-bit geometry caps): fixed.** `validate_resource` rejects total clusters or LOD clusters > 0x400000 (22-bit `kVisibilityGeometryIndexMask` + 1) with a BuilderError citing the visibility ABI; `build_uploadable_scene` re-checks defensively at upload time. IDs past the cap used to alias earlier geometry in readback.
- **LS-56 (benchmark clock): fixed.** The benchmark frame-period sample moved to its own clock variable updated once per frame BEFORE the camera update; the camera-integration dt keeps its own clock. Interactive MoltenVK run (terrace): before `median_ms=0.00 p99_ms=0.41 avg_fps=146552.8` (the camera-update sliver the old shared timestamp left behind), after `median_ms=16.66 p99_ms=18.41 avg_ms=16.69 avg_fps=59.9` (the true vsync-capped inter-frame interval). Fixed-frame runs unaffected in meaning (8.14 ms median on the same scene).
- **LS-57 (non-finite floats and bounds ordering): fixed.** `parse_float` rejects nan/inf (`strtof` parses both without ERANGE); manifest validation requires finite padding and finite, min<=max-ordered explicit bounds; `apply_bounds_padding` (the single choke point for both bound-resolution paths) verifies the resolved bounds are finite and ordered, so negative padding stays legal only while ordering holds (padding -1000 rejected, -0.25 accepted) and NaN source geometry cannot poison the bounds.
- **LS-58 (glTF index range): fixed.** After dense OR sparse index decoding, every decoded index is checked against `positions->count` before the `base_vertex_index` shift. cgltf_validate's own bounds scan covers only the base buffer_view, so a sparse overlay could carry an out-of-range vertex index through; verified with a synthetic sparse-index glTF (index 99 vs 6 positions: rejected with the index and count in the error; the committed dense/sparse fixtures still build byte-identically).
- **LS-59 (v2 record timestamps): fixed.** In `ontos_stream_dump`'s v2 walker, every immediately-decoded record's timestamp is now checked against the current tick (RegionState, BodyState, TotalsState; CellFlipped additionally validates its cell coords against the 128x128 grid) -- mirrors the ontos_view parser, which had the same checks. Queued records were already tick-validated at the next boundary. Verified: flipping one RegionState.t in the window corpus exits 1 (`MISMATCH: RegionState record tick=2 current tick=1`); all 13 committed corpora still verify and the contact WAV renders stay bit-identical (the checks only add rejection paths, no parse change for valid streams).
- **LS-60 (dangling records at EOF): fixed.** After the record loop, a nonempty queue (RegionLevel, RegionCollapsed, RegionMultipole, Contact, RegionRadial, RegionShells) fails with a dangling-record error (exit 2) naming the per-kind counts -- the format has no terminal flush, so such records were previously silently never applied. Verified: appending a valid RegionLevel after the final tick exits 2.
- **LS-61 (publication durability): fixed.** `write_resource` treats a failed temp-file reopen or fsync as a write failure (no rename), and after a successful rename fsyncs the parent directory (POSIX, macOS/Linux clean) so the published name is crash-persistent. `write_summary` gets the same discipline (fsync + rename + dir fsync) it previously lacked entirely.
- **LS-62 (screenshot publication): fixed.** The PPM is written to a temp file in the target directory; stream state is checked after the writes and the close; only a fully written file is renamed into place. A mid-write ENOSPC now yields `capture failed: file write failed` (no `screenshot=` line, no truncated file at the target). Healthy capture re-verified live on MoltenVK (`capture ok`, valid 1280x720 PPM published).
- **LS-23 reopened 3rd time (fingerprint canonical field table): fixed.** `compute_content_fingerprint` and `write_summary` now both consume ONE canonical table of the sidecar's scalar fields (`collect_sidecar_fields` in `builder_serialize.cpp`): asset_id, source_asset, has_fallback, source_vertices, source_triangles, seam_locked_vertices, bounds_min/max, all table counts, geometry/texture byte totals, texture kind + dims, uv_clusters/uv_lod_clusters. A published sidecar field the fingerprint does not cover can no longer exist (single list, no drift). **Fail-closed consequence: fingerprints changed again; .vgeo + .summary.txt pairs persisted before this pass fail the pairing check and must be regenerated.** Schema version stays 6; the documented fingerprint definition in `schemas/VGEO_RESOURCE_SCHEMA.md` now enumerates the table. Verified: a seam_locked_vertex_count-only change (11 -> 12) changes the fingerprint, as do asset_id/texture_width/uv-cluster-count-only changes.
