## Open decisions for the owner

- **LS-24 (contract decision, no behavior change): cross-toolchain byte identity of generated normals is unpinned.** The builder computes normals with host `sqrt`/`acos` and the prototype CMake does not pin FP contraction (`-ffp-contract`), so the same source asset can produce different normal bytes under different compilers/FP environments, and a content-addressed cache keyed on those bytes is not portable across toolchains. Options: (a) pin FP semantics for the builder (contraction off, explicit math where practical) and quantize normals at serialization so byte identity is a contract; or (b) keep generation unpinned and make cross-platform cache tests semantic (compare decoded values with tolerance) instead of byte-exact. Owner to rule; nothing committed either way. The schema-version pin check from LS-25 (`tools/check_schema_version.sh`, CI) is in.

## Residual verification scope (not known defects)

- **Per-frame occlusion paths are compile-verified only.** The drawIndirectCount-path findings (LS-03/05/13 fixes, temporal HZB dispatch) cannot execute on MoltenVK (per-frame refine is epilogue-only there). First run on a non-MoltenVK device should confirm: HZB edge coverage, footprint-max queries, temporal invalidation dispatch, survivor order stability.
- **LS-26/28/32 gates ran on MoltenVK only so far.** The order-preserving run fold, the drawIndirectFirstInstance/multiDrawIndirect/maxDrawIndirectCount gating, and the Vulkan-1.2 `shaderOutputLayer` feature route (vs the EXT extension) all compiled and ran clean on MoltenVK; a non-MoltenVK device should confirm the feature-route device-create chain and that the indirect-count path engages when fully supported.
- **LS-26 accepted perf trade, not yet benchmarked.** Contiguous-run folding raises the fallback encode count from <= 4 quartile buckets to the number of vertex-count transitions in the draw list (order preservation is required for equal-depth determinism). A paired MoltenVK benchmark run should quantify the delta on the city scene; the old numbers (2 encodes, 1.9 ms submit) are no longer representative.
- **LS-31 pipeline default-off.** The cluster_select compute pipeline is only built with `--gpu-selection`; nothing dispatches it, and creation failure is non-fatal. If/when GPU traversal lands, revisit the 11-SSBO layout against minimum descriptor limits.
- **LS-18 viewer port is corpus-verified, not contract-exhaustive.** Tags 11-13 parse and validate against every committed simval corpus (six contact streams bit-identical audio incl. static contactants, re-verified after the LS-33 contact-validation tightening, plus synthetic negative streams: out-of-range monopole id, a past body_count, wall id with walls off, real b past body_count), plus negative tests (unknown tag, misplaced/invalid ContactParams). Future stream-contract tags will need another port pass - the walker still rejects tags above 13 by design.
- **LS-19 perf trade-off is accepted, not benchmarked.** Removing the CPU normal-cone backface cull from the main pass costs draw-list entries and vertex work on cone-backfacing clusters; a paired benchmark run should quantify it. Cone/cull-sphere data remains in the cluster records for future one-sided material support.
